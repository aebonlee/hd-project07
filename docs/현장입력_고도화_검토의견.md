# 현장 입력 고도화 검토 의견서 — 음성·이미지·영상 입력

- 대상: Field-Insight MVP (hd-project07)
- 요청: 정광호 책임 — "위험한 현장에서 화면을 보며 텍스트를 입력하는 것은 불편하고 안전 부담. 음성 녹음·자동 텍스트 변환·이미지/영상 삽입·이를 반영한 AI 분석과 추가 질문 도출을 검토·구현해 달라. 고려사항이나 더 쉬운 대안이 있으면 함께 제시."
- 결론 요약: **요청 5개 항목 모두 브라우저만으로 구현 완료**(외부 서비스는 선택 사항). 다만 STT 방식·미디어 보존 정책·word-level 타임스탬프는 아래 표의 트레이드오프를 확인하고 조직 차원 결정이 필요합니다.

---

## 1. 음성 입력(STT) 구현 방식 비교

| 구분 | ① Web Speech API (현재 기본) | ② Whisper API (현재 선택 옵션) | ③ 사내 로컬 STT (Phase 2 권장) |
|---|---|---|---|
| 비용 | **무료** | 유료(분당 과금) | 서버/GPU 구축 비용, 운영비 |
| API 키 | 불필요 | 필요(사용자 개인 키) | 불필요(사내) |
| 브라우저 | **크롬/엣지 한정** (사파리 일부, 파이어폭스 미지원) | 모든 브라우저(파일 업로드) | 모든 브라우저 |
| 네트워크 | **필요** — 음성이 브라우저 제조사 서버로 전송됨 | 필요 — 음성이 외부 API 로 전송됨 | **사내망만** (보안상 최적) |
| 실시간성 | **실시간 전사** (말하는 즉시 화면 반영) | 녹음 종료 후 일괄 전사 | 구축 방식에 따라 실시간 가능 |
| 타임스탬프 | 없음 → **세그먼트 단위로 자체 기록**(구현함, 아래 3절) | **세그먼트 제공**(verbose_json), word 단위도 가능 | word-level 가능(로컬 Whisper 등) |
| 한국어 정확도 | 양호(소음 환경에서 저하) | 우수 | 모델 선택에 따름 |
| 보안 관점 | 사내 음성이 외부로 나감 — **보안 검토 필요** | 동일 + 키 관리 필요 | **외부 유출 없음** |
| 현재 구현 | 기본값. 녹음과 동시에 텍스트 자동 삽입 | ⚙ 설정에서 키 입력 시 자동 전환 | 어댑터 인터페이스만 정의(교체 지점) |

**권고**: 수업/데모와 PoC 는 ①로 충분합니다. 현장 파일럿에서 정확도가 문제되면 ②로 검증하고, **사내 확산 단계에서는 ③(로컬 STT)이 보안·비용 면에서 최종 답**입니다. 세 방식 모두 동일한 transcript 스키마(`{text, start_ms, end_ms}`)로 저장되므로 엔진 교체 시 데이터 재작업이 없습니다.

## 2. 이미지·영상 첨부 — 용량과 보존 정책 (FR-27)

| 항목 | 현재 구현 | 확산 전 확정 필요 사항 |
|---|---|---|
| 용량 제한 | **영상 50MB / 이미지 10MB / 음성 20MB** (설정 상수, 초과 시 즉시 안내) | 현장 평균 영상 길이 기준으로 재조정. 50MB ≈ 1080p 약 1분 |
| 저장 위치 | 브라우저 IndexedDB (Blob 원본 불변, Issue 에는 참조만 — DP-1) | Phase 2: 사내 오브젝트 스토리지. 브라우저 저장은 기기 분실 시 유출 위험 인지 |
| 보존 기간 | 미설정(수동 초기화만) | **원문 사양 FR-27**: 보존기간·접근권한·마스킹 기준을 개발 확산 전에 확정해야 함 |
| 제3자 정보 | 정책 문구만 표시 | 음성·영상에 **제3자 얼굴/대화**가 섞일 수 있음 → 촬영 가이드(장비 위주 촬영) + 마스킹 절차 필요 |
| 접근 권한 | 역할 모드 수준 | 서버 전환 시 이슈 담당자/관리자만 원본 열람 등 권한 설계 필요 |

## 3. 근거 점프(evidence_ref)와 타임스탬프 수준

원문 사양은 "STT 는 word-level timestamp 를 저장해야 하며, 나중에 소급 적용할 수 없다"고 강조합니다. 현재 구현 상태:

| 수준 | 가능 여부 | 비고 |
|---|---|---|
| 세그먼트(발화 단위) 타임스탬프 | **구현 완료** | Web Speech 는 타임스탬프를 주지 않으므로 각 final 결과의 시각을 녹음 기준 ms 로 자체 기록. 필드 근거 클릭 → 해당 세그먼트부터 오디오 재생 + 전사 하이라이트 |
| word-level | 스키마는 준비됨, 데이터만 세그먼트 | **Whisper(verbose_json + timestamp_granularities=word)** 또는 로컬 Whisper 로 확보 가능. `transcript[]` 구조가 동일해 세그먼트→word 로 촘촘해질 뿐 소급 재작업 없음 |
| 텍스트 char offset | 구현 완료(1차) | 전사 세그먼트 ↔ 최종 텍스트 char 위치 매핑까지 구현 — 텍스트·음성 근거가 한 스키마로 연결됨 |

## 4. 더 쉬운 대안 (구현 없이/최소 구현으로 현장 부담을 줄이는 방법)

| 대안 | 장점 | 한계 |
|---|---|---|
| 휴대폰 기본 **음성 메모 → 파일 업로드** | 교육 불필요, 오프라인 녹음 가능(신호 없는 현장) | 전사는 업로드 후(실시간 아님). 현재 구현이 이미 녹음 파일 전사를 지원하므로 추가 개발 거의 없음 |
| **전화 접수 → 녹취 자동 전사** | 가장 낮은 진입장벽(전화만 걸면 됨) | 전화 인프라 연동 필요, 장비 식별(QR/보유장비)을 별도로 물어야 함 |
| 카카오워크/Teams **음성 메시지 연동** | 이미 쓰는 메신저 그대로 | 사내 보안 정책·봇 연동 개발 필요, 근거 점프용 타임스탬프 확보 별도 작업 |
| 현장 QR + **사진 1장 우선 접수** | "일단 찍어 보내면 접수됨" — 이탈 최소 | 텍스트/음성 없으면 정보충분도가 낮아 추가 질문·전화 확인이 늘어남 |

**권고**: 단기에는 현 구현(녹음 버튼 + 실시간 전사)과 "음성 메모 파일 업로드"의 병행이 비용 대비 효과가 가장 좋습니다.

## 5. 안전 관점 권고

1. **핸즈프리 우선**: 접수 첫 화면 최상단에 대형 녹음 버튼(64px+)을 배치하고, 녹음 중에는 화면을 어둡게 하고 큰 정지 버튼만 노출해 화면 응시 시간을 최소화했습니다. 이동 중·작업 중 입력은 하지 않도록 안내 문구를 권장합니다.
2. **위험 신호 즉시 분기**: 텍스트/전사 텍스트의 위험 키워드(FR-05)에 더해, (정밀 모드) 이미지·영상 분석의 위험 신호(연기·누유 등)도 동일한 긴급 분기로 연결했습니다. 긴급 접수는 질문 없이 즉시 전문가에게 전달됩니다.
3. **촬영 안전**: 위험 상황(화재·전복 등)에서는 촬영보다 대피가 우선임을 안내 문구로 명시할 것을 권고합니다.
4. **정보 품질**: 음성 전사는 오인식이 있으므로, 기존 선택적 확인(저신뢰 상위 2개 강조) 흐름이 그대로 적용되어 오인식 값이 확인 없이 확정되지 않습니다.

## 6. 요청 항목별 구현 현황 매핑

| 피드백 요청 | 구현 | 위치 |
|---|---|---|
| 1. 음성 녹음 버튼·음성 삽입 | ✅ MediaRecorder 녹음(복수 첨부), IndexedDB 원본 보존 | C-01, `app/mediastore.js` |
| 2. 녹음 자동 텍스트 변환 | ✅ Web Speech 실시간 전사(기본) + Whisper 업로드(선택), 세그먼트 타임스탬프 | `engine/stt.js` |
| 3. 이미지·영상 삽입(용량 제한) | ✅ 카메라 촬영/선택, 영상 50MB 제한, 썸네일·플레이어 | C-01/C-03/E-02, `engine/media.js` |
| 4. 입력 내용 기반 AI 분석 | ✅ 텍스트: 규칙 엔진(기본) / 이미지·영상 프레임: 선택 정밀 모드(제공사 키 입력 시) → E-03 미디어 분석 | `engine/aivision.js` |
| 5. 누락 정보 확인용 추가 질문 | ✅ STT 텍스트도 동일 Gap 분석 → DecisionImpact 질문(≤3). 미디어 단서는 미확보도 재평가에 반영 | `engine/gap.js`, `engine/question.js` |
