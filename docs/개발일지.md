## 1. 요구사항 분석

기획서는 수강생 기획서 중 유일하게 **개발 착수용 시스템 사양서 수준**(설계 원칙 DP-1~9, 기능 요구 FR-01~27, 화면 C/E/A/K, 데이터 모델, 상태머신, MVP 범위, KPI)으로 작성되어, 별도 해석 없이 원문을 사양서로 사용했다.

- **범위**: MVP-1만 — 정비 Domain, 텍스트 입력, 전체 루프 1회전 (FR 표의 MVP=1 항목)
- **아키텍처**: Phase 1 — 브라우저 + 로컬 JS + **Mock AI Rule Engine** + localStorage. 외부 LLM API 호출 없음(어댑터 인터페이스만 정의)
- **절대 생략 금지 4요소**: `evidence_ref` · 출처 기반 `confidence` · Issue 상태머신 · 회신 루프

핵심 개념은 단순 정보 추출이 아니라 **Dynamic Requirement Identification** — "이 질문을 해결하려면 어떤 정보가 필요한가"를 먼저 판단하고, **전문가의 판단을 바꿀 질문만 최대 3개** 묻는 것이다.

## 2. 설계 결정

| 결정 | 이유 |
|---|---|
| **데이터 우선** — MNT-01~12 매트릭스·부품 코드 마스터를 코드가 아닌 JSON으로 먼저 정의 | 원문 19장 착수 순서 1~3 준수. 판별력 가중치를 스키마에 사전 정의(LLM 추론 금지 — 재현성) |
| `DecisionImpact = 판별력 × 획득가능성 × 미확보도` 를 순수 함수로 구현 | 원문 8.2 공식 그대로. 획득가능성 '하'(유압 온도·선회 압력)는 질문하지 않고 전문가 추가 확인으로 |
| confidence는 **출처 기반 테이블** (0.95/0.99/1.0/0.6/0.4/0.5) | 원문 9.2 — LLM 자기보고 신뢰도 금지. <0.7 상위 2개만 확인 화면 강조(DP-4) |
| evidence_ref = 입력 텍스트 문자 오프셋 | 텍스트 MVP에서 음성 타임스탬프에 대응하는 근거 점프 구현(DP-2). 필드 클릭 → 원문 하이라이트 |
| 상태머신은 불법 전이 시 예외 발생 | DRAFT→…→KNOWLEDGE_READY 전 상태 + MERGED/STALE/CLOSED_UNVERIFIED, 감사 이력 append-only(FR-25) |
| 전문가 결론의 계통/부품은 코드 마스터 검색·선택만 허용 | 원문 10.3 "자유 텍스트 금지" — 집계·학습 가능성 확보. "원인 미확정" 종결 + 사유 코드 지원 |
| 역할은 계정 분리가 아닌 `user.roles[]` + 화면 모드 토글 | 원문 3장 구현 주의 그대로 |
| 시드 데이터를 손으로 만들지 않고 **엔진을 통과시켜 생성** | ISSUE #1024 시나리오가 실제 코드 경로로 재현됨을 보장 |

## 3. 구현 내역

- **schema/**: 정비 Requirement/Question Matrix(MNT-01~12, 판별력·획득가능성·선택지 원문 그대로), 부품 코드 마스터(10 계통/24 부품 — SW-HYD-0412 포함), 도메인 8종(정비 활성), 미확정 사유 4종. `file://` 실행을 위한 번들 생성 도구 포함(JSON이 원본, 동기화는 테스트로 검증)
- **engine/**: Intent 분류+안전 감지(FR-04/05), Gap 분석(FR-06/07), 질문 엔진(FR-08 — 최대 3개, [모르겠음], 진행 표시), confidence(FR-09), 상태머신+감사 이력(FR-25), Mock AI(FR-12/13/17/20 — A/B/C/D 판정, 자유 서술→4필드 초안, 기술어→고객어 변환)
- **app/**: 접수자 C-01~C-05 / 전문가 E-01~E-05 전 화면, 모바일 우선(터치 48px+), 근거 점프 하이라이트, D 판정 시 [고객에게 추가 확인 요청]→PENDING_FIELD 루프, 승인 게이트(E-05 — 전문가 원본과 고객용 재작성 분리 저장·원본 불변), Knowledge 승격 게이트(RESOLVED+원인확정+승인만, DP-8)
- **seed/**: 원문 15장 End-to-End 시나리오(굴착기 HX220A, ISSUE #1024)를 IN_REVIEW 상태로 재현하는 데모 시드

## 4. 테스트 및 검증

- `node tests/unit.test.js` — **34 통과, 0 실패**: DecisionImpact 수기 검증, confidence 테이블, 상태머신 합법/불법 전이, Intent·안전 감지, 원문 Step 2 Gap 재현, 질문 3개 제한·'하' 제외, Mock AI 판정·4필드 초안·고객어 변환, 스키마-번들 동기화
- `node tests/e2e.test.js` (Playwright) — **12/12 단계 통과**: 시드 확인 → 신규 접수 전체 루프(입력→질문 3개→저신뢰 확인→접수→전문가 큐→근거 점프→AI 분석 B/87%→SW-HYD-0412 확정→승인 발송→해결됨→KNOWLEDGE_READY) + 저장 데이터 검증(감사 체인, 원본 불변성)
